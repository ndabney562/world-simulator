# ADR0034: Real-slice illness and linked consequences

- Status: Proposed
- Date: 2026-10-21
- Decided by: Product Owner's direct #74 continuation and recorded #77 technical delegation; Codex proposal, independent review
- Issue: #101 (design), #74 (runtime)
- Supersedes: none; extends ADR0021's real-slice vocabulary, ADR0033's state and ADR0032's inspection boundary

## Context and options
The user instructed “Merge #98 when CI passes and keep going with illness.” #98 merged with five green checks and clean final-head review. #74 needs duration/severity, missed duty, a neighbour visit decided at L1, recovery and an honest causal query. Initial vitals alone do not implement illness. The toy fever's no-recovery behavior stays unchanged. Health-only UI changes would miss #74; a disease/mortality simulator exceeds it. Choose one deterministic finite episode with actual behavior effects and a bounded produced-consequence query. No new dependency, source, service, death, save format or stage/device claim.

## Decision

### Operation, state and replay
Add a real-slice typed Afflict operation targeting one existing living resident at L1 or L2, applied at the serialized committed boundary without advancing time. Severity is1..10; duration is100000..86400000000 integer microseconds, divisible by100000 (one tick through24hours). Check end-time overflow before effects. Unity's single illness action uses severity5 and two model hours. Health becomes100−9×severity; life remains Alive and sex/age/employment remain unchanged. Recovery at the half-open episode end restores100. No spontaneous illness, contagion, mortality or other health sources are introduced.

Maintain one latest episode per retained resident, with root/illness EventIds, severity, start/end, return-home deadline, recovered/return/missed-duty/visitor state, independent of LOD. Health can change only through the checked core path; mutation is not exposed as a component setter across FFI. Re-afflicting an active illness, or a recovered episode with a still-pending illness-produced return-home arrival, is accepted with affected=0: no second illness, stronger severity, reset deadline or health change. It still records the new intervention root. A recovered person can receive a new episode once that pending produced return is complete (a harmless healthy home hold does not block re-affliction). This preserves the old episode’s still-due return fact instead of overwriting it. Invalid targets/dead/severity/duration/overflow are semantic rejections, recorded in the typed operation/outcome journal with no state/event effect. Add a distinct rejection error so these records can be replayed before later commands; existing environmental-stop handling remains unchanged.

Use the normalized operation-record index as the root's command sequence. Include all episode timers/IDs/flags and retained behavior overrides in canonical hashing; no-episode/no-override paths retain existing hashes/goldens exactly. A versioned slice-state/v3 envelope adds illness policy1 only after an episode exists. Derived consequence indices/capacities do not enter canonical hash. Replay includes commands, rejected outcomes, actual events and future trajectory. Real-slice saves remain #75, which must later pin illness policy and store canonical episodes/overrides; legacy toy saves explicitly reject new slice payloads.

### Continuous behavior and exact counts
Retain immutable baseline timetables and add a versioned temporary behavior override per affected resident. An already-started journey finishes at its original endpoint/time; then the person travels home on the existing navigation graph. Stationary people start their homebound leg now. A local leg takes the existing rounded-up walking ticks; an off-map return takes max(walking ticks,30model minutes), with the existing explicit external-segment proxy and portal projection. A person already home has no invented arrival.

After reaching home, rest while ill. After recovery, finish any already-started homebound journey and stay home until the baseline can be rejoined continuously: immediately if its answer is at that same home, or at the next commute departure whose origin is that home. Never snap to an off-map duty or join a trip halfway through it. Search a bounded sequence of daily boundaries; if the rejoin time lies beyond SimTime, retain the home override without fabricating an in-range transition. Store journey endpoints in i128 like existing schedules; handle negative/extreme times without narrowing.

Behavior preparation drains model-minute decisions plus actual override phase boundaries, integrating each held action exactly. Only real model-minute decisions advance the existing decision counter. Quiet ticks allocate no new illness plan. Fine projection/heading and coarse/common answers use the same effective logical journey; planned snapshots use planned overrides. Pure queries never drain or regenerate state. The camera controller plans against those effective answers in the same transaction, including command boundaries, maintaining one membership, correct occupancy/governed/activity partitions and observations.

Suppress baseline ScheduleChanged facts when actual previous/current activities do not match that transition. Do not emit fictitious work/arrival facts from the original timetable while held home. Record causally linked ReturnedHome only when a new homebound leg produced by this illness completes. A pre-existing journey already headed home is not an illness-produced return; do not invent a causal link from coincident arrival. Track a pending produced return independently of whether health has already recovered. Record missed work/school at an interrupted current duty on application, or at a subsequent baseline duty start that actual behavior cannot attend because of the episode/remaining home override. Distinguish partial interruption from an unvisited scheduled boundary by its occurrence time; never generate facts for before the command.

### L1 neighbour check-in
At model-minute boundaries while the patient is ill and actually at home, choose at most one neighbour for that episode. Both must be L1 at the decision phase before this tick's controller changes. The visitor must be healthy/alive, have no active override, be at Home in the same building but a different household (thus a different synthetic unit), and have no mandatory baseline transition before the end of a five-minute visit. Process patients in ascending resident EntityId order, and choose the lowest eligible visitor ID. Evaluate each choice against the staged behavior overrides and visitors already claimed earlier in this boundary, not a frozen pre-plan snapshot. A visitor can hold at most one active visit; an earlier accepted visit removes that person from later candidates. No eligible neighbour means no visit event; do not invent one at L2, promote anyone or infer a past visit.

The visitor actually holds Socialize for those five minutes at the shared building, then rejoins its baseline continuously. This is a building-level apartment-neighbour check-in, not inter-building travel or unit geometry. The event records the start and intended duration; a later independent intervention may interrupt it. The voluntary-response causal claim is ContributedTo/Contributing, not a proven sole cause. Illness/recovery/missed-duty producer links use CausedBy/Direct; the actual return-home contribution uses ContributedTo/Direct. Nothing claims a counterfactual simulation.

### Events and atomicity
Append payload tags10 MissedDuty(resident,destination,activity),11 NeighbourCheckIn(visitor,patient,home,intended_duration_us),12 Recovered(resident,health),13 SliceIllnessApplied(resident,sequence,severity,duration_us,affected). Reuse LifeIllness5 and ReturnedHome6 with their existing meanings. New root13 uses system10/lod0; illness5 system12/lod0, return6 system50/lod1or2. New systems80/81/82 produce missed-duty/check-in/recovery respectively; neighbor lod is1 and other new consequences use actual1/2. Root13 is recognized by root-intervention traversal. Root has the target as an actor; all consequence participants are explicit registered actors. Existing payload tags, record schema, toy behavior/codecs and goldens remain.

Illness5 is CausedBy/Direct to root13. Each later produced consequence links to that illness event with the relation/confidence above. All IDs/times/actors are actual committed facts; no links from temporal proximity. Sort combined per-boundary candidates canonically by (system,sequence); local references are resolved consistently. Prepare bounded episode/vitals/override/controller changes, history capacity and derived-index capacity before publishing anything. Commit events and all affected state together with no remaining fallible step. An injected planning/history/allocation error preserves the failing boundary, including health, membership, clocks, event IDs/digests and episode/index publication; a batched step preserves only its committed prefix. Operation-journal reservation failure happens before the attempt is recorded.

### Bounded produced-consequence index
Keep a derived index sorted by root13 ID. Each entry holds root metadata and up to16 actual produced EventIds in increasing ID order. The24hour policy allows at most two missed-duty records (including an interrupted current duty), one real home arrival, one neighbour check-in, one recovery, illness and root; the16 cap leaves room without truncating current facts. Unknown roots fail. New producers must fail before commit if they would exceed the cap; never drop history. The index grows with recorded interventions, like the retained event history.

Reserve a new root entry before command publication; existing entries use fixed-capacity ID slots. Stage per-root slot updates alongside event preparation, without cloning/scanning the unbounded history each tick. Rebuild the index from committed typed roots and explicit cause links; legacy toy roots/illness are not real-slice groups. Queries binary-search the root then read at most16 ID lookups; bounded work and temporary memory, no simulation/LOD mutation. The query is this producer-defined illness consequence set, not an unbounded generic descendant closure.

### ABI8 and inspection
Advance global ABI7 to8 (reconcile if already used). Preserve old structures, command envelopes, fixtures/consumer sources and old-client refusal through7. Add real-slice operation tag5: words resident ID, severity full u32, duration_us u64, then three zero words. Full validation precedes effects; malformed framing differs from a semantic rejection. Other operation tags and their layouts stay unchanged.

Inspection schema3 retains the96-byte header, identity schema2 and prior offsets; resident state grows80→112bytes. At state-relative80/84 are override_kind u32 (0none,1illness-home,2visit) and illness_active u32 (0/1);88 override_root_intervention u64;96 last_own_intervention u64;104 current_illness_end i64 (zero when inactive). State-relative56/60 remain health/life. Validate active illness implies living health1..99, future end, own root and illness override. No override requires root=0 and full baseline timetable/activity correspondence; active overrides allow only valid registered endpoints and the specified home/commute semantics instead of falsely requiring the base activity. Last-own-root may survive recovery to inspect recorded history. Building state remains48bytes. Retain all existing caps/strict UTF8/tag/schedule/atomic publication checks.

Extend existing80-byte recent-event payload projection for tags5/6/10/11/12/13; old7/9 remain. New row payload words in order:5 resident,illness,severity,0,0;6 resident,home,0,0,0;10 resident,destination,activity,0,0;11 visitor,patient,home,intended_duration,0;12 resident,health,0,0,0;13 resident,sequence,severity,duration,affected. Unknown payloads still fail explicitly.

Add ws_slice_consequences(handle,root,buffer,capacity,written), same8192-byte cap and short/error/unwind preservation rules. Header96: ABI/size at0/4; tick/time/hash/dataset at8/16/24/32; root/subject at40/48; total/count/stride128/flags0 at56/60/64/68; schema1/severity at72/76; applied time/end time i64 at80/88 (end0 when affected0). Follow with at most16 rows of128bytes: existing event80-byte projection at0; cause count at80,zero at84; parent1 ID/relation/confidence at88/96/100; parent2 at104/112/116; zero u64 at120. Unused parent slots are zero. Validate all lengths/tags/order, no future event time, causes pointing earlier within the returned group with known relations/classes, root/subject metadata and direct-vs-contributing shapes.

The existing five-field person view stays. One context-sensitive illness action applies severity5/two hours and opens a separately labeled consequence readout; in that view the control refreshes the same root without applying again. Re-tapping the person returns to the five-field sample. Existing close still clears inspection. No background polling, editor, composer or extra always-visible person attributes. Native apply/sample/consequence/sky reads use the existing serialization gate; the host closes the old pacing interval before an action. Publish a complete coherent UI result, or retain the previous one with an error.

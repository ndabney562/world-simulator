# ADR0033: Resident sex, health and life status

- Status: Accepted
- Date: 2026-10-21
- Decided by: Product Owner request, Codex proposal; independent review and recorded technical delegation on #77
- Issue: #99; runtime extends #73
- Supersedes: none; extends ADR0032's inspection wire contract

## Context

The Product Owner requested actual sex, health and alive/dead values, keeping the resident panel at five fields including age and employment. The real-slice core currently lacks these attributes. UI constants or inference from names/needs would not model them. ADR0032 owns the bounded read-only query. Existing synthetic population1, ID, schedule, behavior and topology goldens remain valid. The TP-010 toy Illness state is separate; #74 will integrate illness into the real slice and explicitly excludes deaths.

## Options considered

1. Unity defaults: cheap but not authoritative, rejected.
2. Full demographic/disease/mortality model: adds behavior beyond this request, rejected for this increment.
3. A small independently versioned core column with explicit initial values and a versioned inspection extension: chosen.

## Decision

### Core state and baseline

Add resident-vitals policy1 as a separate column keyed by the exact retained resident EntityIds, initialized once when SliceSimulation is created. Do not regenerate it on inspection, camera changes or LOD transitions. All retained residents have exactly one row; context/buildings have none. Borrow its values in the pure inspection projection.

Sex tags0 Female,1 Male are generated by `below(Stream(seed, Purpose::new("ws-world/slice/vitals/sex/v1"), &[resident.raw()]).draw(0), 2)` using the existing integer primitive. Equal synthetic probabilities are an explicit small baseline policy, not a claim about actual Brooklyn residents or a full biological/demographic model. Sex is independent of names, age, job and other streams. Future expanded categories require a reviewed policy/tag extension. No existing identity, population stream or population1 baseline/golden changes.

Each row stores health0..100 and life status0 Alive/1 Dead. Creation initializes health100 and Alive. Valid states require Alive with health1..100, or Dead with health0. Health is a coarse model quantity, not a medical assessment. No aging, spontaneous illness, recovery, mortality event, death command or altered schedule/need/navigation behavior is introduced here. The stored health/life values remain constant until separately authorized dynamics exist; future illness work must respect these invariants. Never describe this increment as functioning disease/death mechanics.

Use checked construction and typed tags. Canonical vitals digest includes policy1, all row IDs in ascending order, sex, health and life status. Extend the real-slice canonical state hash with a newly domain-separated envelope over the previous real-slice state hash, vitals policy and digest. Preserve the previous hash routine privately for exact regression coverage; do not replace existing lower-level Tier1 goldens. Add new independent vitals goldens and prove changing each field changes the new canonical hash. Existing operation/checkpoint/replay uses the complete new hash. Seed plus pinned vitals policy reproduces initial values; queries remain pure and side-effect free.

The real slice still has no persistent save format (#75). No legacy toy save/header/event schema changes; real-slice saves must later pin this policy and serialize health/life deltas. Creation facts remain the existing SliceCreated event; no fictitious per-person sex/health/life transition events are emitted for initial state.

### Wire contract

Advance global ABI6 to7 (if unused when runtime begins), preserving all previous structures/operation layouts, prior fixtures and consumer sources. Old clients refuse ABI7 before decoding. Add v7 fixtures and a v7 C consumer that retains previous positive checks. Advance current success consumers and old-version refusal cases together; no skipped/loosened checks.

Inspection header remains96 bytes, but inspection schema at offset48 becomes2. Identity-section schema becomes2 for either entity kind. Resident identity retains home/household/workplace u64 and age/role u32, then adds sex u32 before the two strings (sex is at absolute136, strings at140). Identity size is therefore4 bytes larger. Building identity fields and sizes remain unchanged except its schema word.

Resident state remains80 bytes: its former reserved u64 at state-relative56 is replaced by health u32 at56 and life status u32 at60. Other state/schedule/event fields, building48-byte summary, caps8192/1024/128/32/16, string rules and publication/failure semantics remain ADR0032. Schema1 remains represented by retained v6 fixtures, not silently reinterpreted as2.

Managed decoding validates ABI7, schema2, sex0/1, health0..100, life0/1 and the health/life invariant before publishing a complete record. The panel reads decoded values: Age, Sex, Employment, Health (N/100), Alive/dead (Alive or Dead). There are no missing-value defaults or inference. Exactly one bounded tap-driven query remains; no polling or extra frame allocations.

### Verification and sequencing

Merge this independently reviewed docs-only decision before runtime. #73's existing user authorization covers this extension; record it on #73/#99. The named technical delegation on #77 still requires independent exact-published-head review and all five green checks before technical acceptance/merge. No signing/device/stage gate is delegated here.

Runtime tests must prove one row per resident and no unknown lookup, checked enum/range/invariant rejection, deterministic independent sex golden including both tags, seed/ID stability and independence of old baseline streams, unchanged old population/schedule/behavior goldens, state-hash sensitivity to each field, repeated inspection purity, time/camera/LOD/replay preservation and equal future trajectory. Preserve old hash behavior under a dedicated regression. No mutation API for health/life is exposed by this increment.

Native/shared fixtures and C/managed tests cover all new offsets/tags, contradictory life/health pairs, truncation, version refusal through6, short/error/unwind output preservation, and no partial managed replacement. Test formatter output for both sexes and valid healthy/ill/dead constructed records (these test records are not spawned residents). Run pinned Rust/Unity suites, source-only static checks and capture the actual native-backed five-field panel with real values. Device acceptance stays open.

## Consequences

Rust owns real retained attributes; presentation no longer says Not tracked. Initial cohorts are all healthy/alive by an explicit baseline rule; only sex varies now. Adding transitions later will require complete schedule/LOD/occupancy/event/persistence handling, not a UI toggle. No new dependency, data source, account, cost, existing golden replacement or medical claim is introduced.

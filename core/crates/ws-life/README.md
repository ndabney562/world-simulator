# ws-life

Owns immutable real-slice schedule profiles and pure L2 activity/location queries under [ADR 0027](../../../docs/adr/0027-slice-schedules-and-events.md). Dependencies point only to foundation/world/events; there is no simulation, persistence, platform or presentation dependency. Schedule templates, topology, path selection and pure need/utility arithmetic are integer Tier 1. Evolving behavior/orchestration replay is tested as Tier 2 within one build/platform. There is no mutable RNG, clock ownership, event-store feedback or I/O.

`Schedules::new(&population, schedule_epoch)` uses an explicit Monday midnight in a seven-day **model phase**. VS-007 owns civil New York calendar alignment. Every household gets a fixed -15..=15 minute shift from draw zero of `ws-life/schedule/household-jitter`, addressed by household ID. This shifts every non-midnight boundary; intervals stay positive and half-open.

| Profile | Minutes after midnight before household shift |
|---|---|
| Employed weekday | 0 sleep; 390 home; 450 outbound commute; 480 work; 1020 return commute; 1050 home; 1080 shop commute; 1090 errands; 1120 home commute; 1130 home; 1320 sleep |
| Student weekday | Same, with school at 480, return commute at 900, home at 930 |
| Preschool/retired, or any weekend | 0 sleep; 480 home; 660 shop commute; 670 errands; 700 home commute; 710 home; 1320 sleep |

These are synthetic coarse timetables. Journey durations do not measure road distance, including travel between uses in one building. L1 paths/needs follow ADR 0028 below. Off-map work/school retains workplace and exit IDs; the person is never removed. `Location` is one stationary place or one journey with both endpoints. Journey times use i128 absolute microseconds so an interval intersecting a SimTime endpoint retains exact scheduled endpoints. Ordinary queried/current time remains SimTime/i64; no saturation occurs.

`facts_at` plans typed `agent.schedule_changed` facts sorted by resident ID (producer 60, LOD2, subject resident/object destination, no invented causal links). The caller owns transactional event publication. Midnight does not invent sleep-to-sleep changes. Queries and next-boundary reconstruction do not mutate canonical state.

Tests compare every resident over a full week and before the epoch against independently written interval lists; exercise exact boundary ownership, negative/extreme times and off-map conservation; and freeze tables/draws in `tests/golden/schedules.txt`. The separate Python oracle `scripts/vs_schedule_golden.py` reads the previously frozen population fixture and independently computes the new counter draws/tables. Existing goldens remain unchanged. Run `cargo test -p ws-life` from `core/` and `python3 scripts/vs_schedule_golden.py check` from the repository root.

## VS-005 needs, utility and navigation

[ADR 0028](../../../docs/adr/0028-slice-l1-needs-and-navigation.md) pins separate behavior/navigation rules version 1; schedule/structural/population versions and old goldens are unchanged. `navigation::Navigation` derives a padded perimeter from all 58 source footprints, maps the four building centroids/two exits to portal proxies and caches integer shortest paths. These are synthetic sidewalk/entrance proxies, not surveyed geometry or an ENU/terrain frame. The approximate plane uses the exact source origin plus fixed integer local scale factors; rendering must adapt it explicitly. Edges stay on the padded envelope, all weights are positive, and full node-sequence lexicographic ties are deterministic. `Graph::shortest` itself allocates nothing; the cache is derived.

`behavior::Behavior` retains sorted resident IDs, levels, need values/anchor time, held action and decision counters. Its immutable schedule copy and navigation graph are baseline inputs. Rest/hunger/social/duty are bounded deficits; `Needs::advanced` integrates a held action with a wide clamped linear formula. Minute decisions use the ADR's fixed weighted utilities at Home; Sleep/Commute/Work/School/Errands constrain the action. New counter purposes initialize needs and resolve equal-score choices. Decisions occur at creation/model-minute boundaries, never as a side effect of a query or a level change.

`prepare(time)` reserves and calculates every intervening minute in a borrowed transaction; dropping it leaves the domain unchanged, and `commit` cannot fail or allocate. L2 catch-up drains exactly the same decisions/counters and preserves needs. `advance_to` is a standalone headless convenience; ws-sim owns the actual clock. Snapshot requests require a grid time within the committed anchor/minute window. `SetDetail` is orchestrated by ws-sim; no mutation escape exists through its read-only behavior view.

Fine location is one local graph point (walking or portal waiting), off-map transit, or stationary off-map identity. Local travel uses140mm per100ms tick and waits at the destination until the unchanged schedule boundary. Off-map departures walk to an exit first; returns spend the external segment off-map, then walk from the exit during the final `ceil(distance/140)` ticks before arrival. The last step clamps to the exact portal. Same-place journeys retain a zero-length path and unchanged schedule interval. Every route is checked against the timetable before construction succeeds.

State classes: population/schedules/graph rules are baseline; resident needs/anchor/action/counter/level are canonical; fine positions are reconstructable; path and next-minute caches/capacities are derived. L1/L2 zero-time round trips retain the canonical hash and exact position. Elapsed-time catch-up preserves exact needs/actions/counters/positions, exceeding the unchanged toy's tolerances. No illness/relationship/crowd/economic model or new factual event is introduced.

New `tests/golden/behavior.txt` comes from `scripts/vs_behavior_golden.py`: an independent integer source projection and exhaustive simple-path oracle using the previously frozen population IDs, plus initial/tie counter draws. Tests cover a physical-tick needs reference, actual fine commute positions/deadlines over a week, full-week coarse/minute equivalence, extreme/negative epochs, graph errors/ties, mixed-level property tests and dropped/overflowed plans. Existing schedule, building, resident and save fixtures remain intact. See [verification](../../../docs/verification/issue-69/README.md) for measurements and remaining scope.

## VS-006 camera controller and counts

`lod::Controller` implements [ADR0029](../../../docs/adr/0029-slice-camera-interest-and-aggregates.md). A single integer `CameraInterest` uses the approximate navigation plane, with radius0 selecting overview. Four canonical nodes select L1/L2/L3 at200-ms model boundaries, with20m exit hysteresis and1s mode dwell. Overview and warp above10× can coarsen immediately at a policy update; promotion retains dwell. Accepted input alone does not tick, reset dwell or draw utility randomness. No camera input leaves manual headless levels available; after ownership begins, ws-sim rejects all manual detail operations.

L3 summarizes retained coarse identities rather than creating another population. AtBuilding occupants contribute once to one building and one Activity bin; transit and off-map stationary totals are separate. Governing-node ownership uses the current local destination, or immutable home for outbound/off-map residents, and is named separately from occupancy. Automatic L1 requires an L1 node and a current local projection. Membership reconciles on every physical tick, including gateways between policy updates. Common snapshots avoid rebuilding fine geometry for count checks; the cached logical answer is derived at each minute, when all schedule boundaries occur, and is excluded from canonical hashing.

Controller preparation stages four node records, member changes and any bounded observation buffer inside the same borrowed behavior transaction. It validates complete unique identities, known buildings, need bounds and exact occupancy/activity/level partitions before publication. Dropping either plan publishes nothing. `Change::fact` plans tag9 `sim.slice_lod_changed` candidates; the owner publishes them atomically with schedule facts. No domain reads factual history to decide behavior.

Recent observations retain the complete FineLocation union and actual automatic-demotion time for an inclusive120 model seconds, including the exact off-map variant at a gateway. Hits reconstruct current positions from retained state; misses/expiry/cache dropping produce the same view, needs and counters. Cache storage/capacity is derived and excluded from hashes. Canonical camera state consists of policy version/input and node mode/change times; the owning slice also hashes common resident levels. A valid camera change may change this whole-state hash; conserved resident quantities are tested separately.

`tests/camera.rs` runs1000 randomized zoom cycles per property case, a maximum30-resident seed71449 through1000 additional cycles, an independent individual aggregation on every tick of a week, extreme epochs/coordinate ranges, off-map cache-hit/expiry boundaries and transaction-drop checks. See [issue-70 verification](../../../docs/verification/issue-70/README.md). No FFI, renderer, cohort economics or device result is introduced.
